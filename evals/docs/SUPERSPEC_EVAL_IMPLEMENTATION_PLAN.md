| 字段 | 值 |
|---|---|

| 目标 | **最小成本**打通「模拟人用 SuperSpec 把需求做到完成 + 双审 + 归因 + 回归」，切断「更新→人测→弃用」死循环 |

## 0. 最小化判断（先说砍了什么、为什么）

| 砍/延 | 理由 |
|---|---|
| **不做任务生成器**（架构 R5） | 手写任务池够用；生成是后置优化 |
| **不做 Docker** | 工作副本 + 固定版本就够（隔离 + 多次运行可比较）；Docker 是对抗沙箱，本系统不要 |
| **不做通用工作流适配器** | 只评 SuperSpec；直接接它的 `events.jsonl`/`snapshot.json`，省一层抽象 |
| **不做多后端** | 工作者钉 Codex CLI（已选） |
| **不做监控 UI** | Markdown 报告够看 |
| **真实性判定的依据** | SuperSpec 引擎**本来就会**往 `events.jsonl` 写每次状态推进事件，所以「绕过引擎直改文件」能直接发现。引擎里的 `actor` 字段是环境变量、工作者可改，真实性判定改用「调度器亲眼看到工作者发起命令 ↔ 引擎事件」一一对应 |
| **双审 + 归因放同一里程碑** | 合并架构 R2+R3 一个阶段做完：**两位独立评审** + **规则归因器**；先跑通，拆分留到后续 |
| **现有 evals/ 代码** | 作为零件复用（Codex 会话辅助、trial 布局），语义按本架构定义 |

> 借的零件：测试壳 / Codex CLI（工作者运行时）/ 工作副本（隔离）/ AI 评审（双审）/ SuperSpec 自带事件（真实性依据）。
> 手写的胶水：调度器中立 + 真实性校验 + 双审材料包 + 归因 + 回归集。这是任何评 SuperSpec 的系统都必须有的领域层，不是重复造轮子。

## 2. M1 — 走通骨架

**目标**：一个手写任务，能在隔离里让模拟用户 + 工作者用 SuperSpec 跑到 `explore`（或 `propose_ready`），并留下全程日志 + 结果判定。**此时还没有真实性判定，输出标 `PROVISIONAL_DONE`。**

### 交付物（文件）

| 文件 | 职责 | 借/写 |
|---|---|---|
| `src/task.ts` | 任务定义类型 + 加载器 | 写（小） |
| `tasks/smoke-explore.json` | 1 个手写任务（需求 + 目标态 `explore` + 预算） | 写 |
| `src/arena.ts` | 物化工作副本 + 装 SuperSpec skills + 固定 openspec/codex 版本 | 复用现有 trial-setup 逻辑，按本架构定义语义 |
| `src/director.ts` | 轮流发言：模拟用户 → 工作者交替；**只转发，不碰状态**；**禁止调用** `transition *` / `record *`（含 `record user-decision`）/ 任何会写 events.jsonl 的命令——这些只能由模拟用户（record）/工作者（transition）经命令行触发 | 写（核心承重） |
| `src/agents/user-sim.ts` | AI 扮用户：给需求、澄清、按引擎给的选项确认 | 写（借 DeepEval 人设模式） |
| `src/agents/worker.ts` | 封装 Codex CLI 跑工作者 | **借** spike-session-helpers |
| `src/transcript.ts` | 只追加，带「谁/何时/为何」；中继 SuperSpec events.jsonl；**工作者的动作记录必须是调度器对 Codex CLI 子进程的外部观测**（命令行、退出码、时间），**工作者不得自报**；自报记录 → 这次运行 `INVALID` | 写（承重） |
| `src/grading/outcome.ts` | 读 `snapshot.json.state == 目标` + 产物在；snapshot 缺失（首次推进前）→ `NOT_DONE` + 原因（不崩） | 写（小） |
| `src/runner.ts` | 串一次运行：考场→调度器→日志→结果判定→报告 | 写 |
| `src/cli.ts` | `run --task <路径>` 入口 | 写（小） |

### M1 出口（可验证）

- [ ] `node --experimental-strip-types src/cli.ts run --task tasks/smoke-explore.json` 跑完不崩
- [ ] transcript.jsonl 有模拟用户/工作者/引擎事件，带归属
- [ ] 结果判定给出 `PROVISIONAL_DONE` 或 `NOT_DONE` + 理由
- [ ] 调度器**和模拟用户**全程没改 SuperSpec 状态（查代码 + 运行时**没有任何状态推进发生在调度器拉起的工作者命令窗口之外**；用时间窗口判断，**不用 actor 字段**）
- [ ] 日志里工作者动作来自调度器外部观测（非工作者自报）
- [ ] 报告 markdown 能给人看

- 双审/归因（M2）

## 3. M2 — 真实 + 复盘

**目标**：在 M1 骨架上加「真假绿识别 + 双角色复盘 + 归因」。这是切断死循环的**核心价值层**——没这层，机器化空洞绿会重现人测的死循环。

### 交付物

| 文件 | 职责 |
|---|---|
| `src/grading/liveness.ts` | 对每个引擎事件找匹配的工作者动作（**不看 actor 字段**；匹配靠调度器外部观测命令 + 引擎事件时间对应，见下）；直改文件没事件 → `INVALID` |
| `src/grading/review.ts` | 两位独立 AI 评审（结构化 JSON：问题 + 优化建议 + 证据指向） |
| `src/grading/attributor.ts` | 规则映射：问题 + 真实性/结果 → 责任类（题/模拟用户/工作者模型/skill/引擎/环境） |
| `tasks/negative/*.json` | 作弊任务：故意注入作弊（调度器改状态 / 工作者绕引擎改文件），验被识破 |
| `src/grading/bundle.ts` | 组脱敏材料包喂评审（任务公开部分 + 结果 + 日志切片） |
| `src/grading/anchor.ts`（可选） | 重算事件摘要链 + 快照摘要串联，断链 → `INVALID`（更强的防伪造，不改产品） |

### 真实性判定怎么落地（关键；不改产品）

SuperSpec 引擎已有：
- `.superspec/changes/<id>/events.jsonl`：每次状态推进必加事件 → **直改文件没事件 = 可免费发现**
- `snapshot.json`：含 `state` → 结果判定可读

**以下字段不能用作真实性依据：**
- `actor` 字段是环境变量（`SUPERSPEC_ACTOR`），工作者可改 → **真实性判定不看 actor**
- 引擎事件里没有「为何/cause」字段
- 事件摘要是写了但不校验 → 更强的防伪造（断链检测）要做就在评测侧 `anchor.ts`

**真实性归属 = 调度器外部观测**：
- 每条状态推进事件，必须在日志里找到**一条调度器亲眼观测到的工作者命令调用**（命令行含 superspec + 时间在事件之前）作为因
- 归属**不靠引擎背书**，靠「调度器看到的子进程调用 ↔ 引擎事件」时间对应
- 对不上 → `INVALID`

> 所以实现**不需要改 SuperSpec 引擎**；真实性判定在评测侧完成。

### M2 出口

- [x] 正向任务到目标状态且真实性过 → `DONE` / `DONE_BUT_FLAWED`
- [x] 作弊任务（调度器改状态、绕引擎、伪造命令归属、篡改事件链）→ `INVALID`
- [x] 双审稳定产问题（带证据指向；无效引用降权）
- [x] 归因给出责任类并生成去重待办
- [x] M2 正向任务不再输出 `PROVISIONAL_DONE`

## 4. M3 — 回归（切断死循环的落点）

**目标**：工作流每次更新后自动跑绿任务集 + 作弊任务集，退化阻断。

### 交付物

| 文件 | 职责 |
|---|---|
| `src/regression.ts` | 跑任务集 + 多次运行稳定性统计 |
| `tasks/green/*.json` | 绿任务集（人工挑的稳定 DONE 任务） |
| `tasks/negative/*.json`（扩） | 作弊任务集（M2 已起） |
| `src/report.ts` | 汇总：绿任务集稳定性 + 作弊任务集识破率 + 退化告警 |

### M3 出口

- [ ] 绿任务集多次运行稳定；作弊任务集 100% 识破
- [ ] 故意改坏一个 skill → 回归报退化（验证门有效）
- [ ] 命令一键跑

---

## 5. 任何时候都不能破的不变量

1. **调度器永不改 SuperSpec 状态**
2. **状态推进只认 SuperSpec 引擎自产的事件**（直改文件没事件 → `INVALID`）；谁触发的，靠**调度器外部观测命令**，**不看 actor 字段**
3. **没有证据指向的归因条目降权**
4. **M1 输出强制标 `PROVISIONAL_DONE`，不得当人测替代/发布门**
5. **作弊任务集和绿任务集同等阻断**
6. **不改产品 `src/`**（真实性依据免费部分够用；要更强防伪造就在评测侧 anchor.ts，不改产品）

---

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| M1 没真实性判定，空洞绿风险 | 强制 `PROVISIONAL_DONE` 标注；M1 不入回归门 |
| 模拟用户不像人 | 人设显式 + 能拒能问 + 选项来自引擎实时 |
| Codex/模型不稳定 | 多次运行统计稳定；单次失败不阻断 M1 出口 |
| 双审说空话 | 强制证据指向，否则降权 |
| 复用代码语义漂移 | 每复用一处都按本架构语义实现 |
| 范围蔓延 | 严格按 M1→M2→M3；生成器/Docker/通用适配器/多后端一律延后 |
